# Mode `report`

Use `report` for longer synthesis after the conceptual target is already clear.

## Best Use Cases

- hypothesis-test memo
- corpus-based evidence summary
- structured literature synthesis
- research note for later reuse

## Preferred Inputs

Consume inputs in this order:

1. existing `Research Brief`, if available
2. recommended fichas from the brief
3. source-registry notes from the brief
4. prior memos, if explicitly relevant

Expand beyond the brief only when the brief is insufficient for the requested output.

## Workflow

1. Read the brief.
2. Open the recommended files.
3. Fill evidence gaps only where necessary.
4. Draft the memo.
5. Label what is direct evidence, inferred synthesis, and unresolved uncertainty.

## Output Discipline

- keep the memo anchored in the fichas
- cite which notes support each important section
- preserve temporal sequence
- preserve scalar scope
- do not treat a previous memo as primary support

## Writing Rules

- if the user asked only for chat output, do not create files
- if the user asked for a file and gave a path, write there
- if the user asked for a file but did not give a path, ask first

## Report Failure Modes

Avoid:
- redoing the frontier stage from scratch
- reopening the whole wiki without a reason
- smuggling unsupported claims into polished prose
- converting thin indirect evidence into a strong conclusion
